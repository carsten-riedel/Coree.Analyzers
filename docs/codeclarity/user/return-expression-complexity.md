# Return expression complexity

CodeClarity diagnostic CCCRC001 warns when a `return`, `yield return`, or returned arrow expression contains more calculation steps than allowed. A `return` or `yield return` says to extract the extra steps into local variables. A returned arrow cannot declare a local, so that warning says to move the arrow into a block and extract the extra steps there. `ReturnTypeComplexityAnalyzerMaximum` sets the limit. The default is 1.

Each of these counts as one step: an arithmetic operator other than built-in string concatenation, a shift (`<<`, `>>`, or `>>>`), a method call other than the `nameof` operator, a conditional operator (`?:`), and a user-defined `operator +`. `&&` and `||` do not count. A user-defined addition counts even when one operand is a string. Built-in string concatenation does not count. The C# `nameof` operator does not count, including when the maximum is 0. A call to an ordinary method that is only named `nameof` or `@nameof` does count.

At the default maximum, `return a + b` stays quiet and `return a + b + c` reports. A `yield return` expression uses that same score. `yield return a + b` stays quiet, and `yield return a + b + c` reports. `yield break` has no value expression and stays quiet.

An expression-bodied member uses that same score when the arrow expression is the returned value. `int Height(int a, int b, int c) => a + b + c` reports at the default maximum. `int Height(int a, int b) => a + b` stays quiet. A void arrow, a constructor, a setter, a lambda, and an async method that returns a non-generic `Task` or `ValueTask` stay quiet, because those arrows are not returned values. The warning on that arrow says to move it into a block first. It does not say to extract locals inside the arrow. Moving a calculation from `return` to `yield return`, or to an arrow that returns that value, does not remove the warning.
